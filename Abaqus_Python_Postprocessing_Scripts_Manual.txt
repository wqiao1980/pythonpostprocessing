1. GENERAL RULES AND QUICK START
================================

Use an Abaqus Command Prompt, not an ordinary Python installation. The ODB
modules are supplied by Abaqus.

To work from the script folder:

    cd /d "C:\python_aba\takeoutSFSM"

Eleven scripts use this launcher:

    abaqus python "C:\python_aba\takeoutSFSM\SCRIPT_NAME.py" [script options]

The local-U2 script is the only exception. It needs Abaqus/Viewer's NODAL
transformation and uses:

    abaqus viewer noGUI="C:\python_aba\takeoutSFSM\extract_u2_local_selected_steps.py" -- [script options]

The standalone -- before the U2 script options is required. For example:

    abaqus viewer noGUI="C:\python_aba\takeoutSFSM\extract_u2_local_selected_steps.py" -- --input-dir "C:\Data\ODBs" --output-dir "C:\Data\Results"

If the separator is omitted, Abaqus may interpret --output-dir as a Viewer
option and report that command-line option "-output-dir" may not be used with
Viewer.

Help for an abaqus-python script:

    abaqus python "C:\python_aba\takeoutSFSM\SCRIPT_NAME.py" --help

Help for the U2 Viewer script:

    abaqus viewer noGUI="C:\python_aba\takeoutSFSM\extract_u2_local_selected_steps.py" -- --help

Quote every path or name that contains spaces. Examples in this manual use:

    ODB input folder: C:\Data\ODBs
    Output folder:    C:\Data\Results
    One ODB:          model.odb
    Instance:         PART-1-1

Create the output folder before redirecting console text into it:

    mkdir "C:\Data\Results"

To capture everything displayed by Abaqus and the script:

    abaqus python "C:\python_aba\takeoutSFSM\SCRIPT_NAME.py" [options] > "C:\Data\Results\console.txt" 2>&1

Use > to overwrite the console file. Use >> to append to it.

3. COMMON CONVENTIONS
=====================

ODB selection
-------------

For most scripts:

* --input-dir identifies the folder searched for ODB files. If omitted, the
  script's own folder is used.
* --odb selects one ODB. A relative name is resolved under --input-dir.
* Repeat --odb to process several named ODBs.
* If --odb is omitted, every .odb directly in --input-dir is processed. The
  search is not recursive.
* --output-dir selects the output folder. If omitted, --input-dir is used.
* --output-name is permitted only when exactly one --odb is supplied.

Example, one ODB:

    --input-dir "C:\Data\ODBs" --odb "model.odb" --output-dir "C:\Data\Results"

Example, two named ODBs:

    --input-dir "C:\Data\ODBs" --odb "model1.odb" --odb "model2.odb" --output-dir "C:\Data\Results"

Example, all ODBs in a folder:

    --input-dir "C:\Data\ODBs" --output-dir "C:\Data\Results"

Step selection
--------------

Where supported, exact step names are entered after --steps:

    --steps "Step-2" "Step-5" "Operation"

An inclusive numeric range uses 1-based ODB step positions:

    --step-range 3 7

An inclusive named range uses the exact first and last step names:

    --step-range "Preload" "Operation"

To select one step by number on a script that has --step-range, enter the same
position twice:

    --step-range 7 7

--steps and --step-range are alternatives; do not use both in one command.
The S11 delta scripts are different: they use one or more --step-pair FIRST
SECOND options, and FIRST/SECOND may be exact names or 1-based positions.

Frame selection
---------------

Where --frame-index is available, it is zero-based:

    --frame-index 0     first frame
    --frame-index 1     second frame
    --frame-index -1    last usable frame; this is the default

The history and S11 delta scripts intentionally read all frames and therefore
do not have --frame-index.

Element selection
-----------------

Depending on the script, selectors are named --element..., --pipe-element...,
--connector-element..., or --spring-element.... Repeat set/range options when
necessary. Sets, exact labels, and ranges are combined as a union.

    --element-set "SET_A" --element-set "SET_B"
    --element 1001 1002 1005
    --element-range 1001 1200 --element-range 2001 2200

    --pipe-element-set "PIPE_SET"
    --pipe-element 1001 1002
    --pipe-element-range 1001 1200

Path endpoints and distance
---------------------------

Scripts with start and end controls generally use this order:

1. Exact labels from --start-node and --end-node.
2. Exact node-set names from --start-node-set and --end-node-set.
3. Unique node-set names containing START and END, case-insensitively.
4. Suitable graph endpoints when the route is unambiguous.

The start-set and end-set names do not have to be exactly START and END. Use
the listing option to identify possible names, then specify the exact set if
more than one name contains START or END.

Path distance is cumulative 3D length along connected elements using original
ODB nodal coordinates. It is not straight-line distance from the first node.

Output and Excel
----------------

The .rpt and .txt files are plain/tab-delimited results. Excel .xlsx files
contain native editable charts. Excel does not need to be installed or open
while Abaqus produces them. Existing output files with the same names are
overwritten, so close an output workbook in Excel before rerunning.


4. HOW TO STOP A RUNNING SCRIPT
===============================

Preferred method
----------------

1. Click the running Abaqus Command Prompt so it has keyboard focus.
2. Press Ctrl+C.
3. If Windows asks "Terminate batch job (Y/N)?", type Y and press Enter.
4. If Ctrl+C does not respond, try Ctrl+Break and wait briefly.

Some ODB field reads execute inside Abaqus code, so interruption may not be
recognized until the current read returns.

Last-resort command from a second Command Prompt
------------------------------------------------

First list candidate processes and identify the exact PID belonging to the
postprocessing command:

    tasklist /V | findstr /I "abaqus viewer python"

Then replace 12345 below with that exact PID:

    taskkill /PID 12345 /T /F

/T also terminates child processes and /F forces termination. Do not use a
broad command such as taskkill /IM python.exe /F or taskkill /IM abq*.exe /F;
it could stop another Abaqus analysis or an unrelated Python job.

ODBs are opened read-only, so stopping postprocessing does not modify the ODB.
The current .rpt, .txt, .xlsx, .log, or console file may be incomplete. Rerun
the same command to overwrite it. A forced stop of an S11 delta run can leave
an s11_intermediate_*.tmp file in the output folder; delete it only after
confirming that the postprocessing process has stopped.

5.1 extract_sfsm_reports.py
---------------------------

What it does

Extracts ESF1, SF1, SF2, SF3, SM1, SM2, and SM3 at ELEMENT_NODAL position.
Integration-point values are extrapolated to element nodes and contributions
at each requested node are averaged. It processes all steps by default and
uses the last frame containing all requested fields.

Default node set: PART-1-1.START
Default report for model.odb: model.rpt
Launcher: abaqus python
Dependency: none

Complete option syntax

    extract_sfsm_reports.py
        [--input-dir DIR]
        [--odb ODB] ...
        [--output-dir DIR]
        [--output-name NAME]
        [--node-set INSTANCE.SET]
        [--steps STEP [STEP ...]]
        [--frame-index INDEX]

Help

    abaqus python "C:\python_aba\takeoutSFSM\extract_sfsm_reports.py" --help

One ODB

5.12 extract_pipe_s11_delta_step_pairs_four_angles.py
------------------------------------------------------

What it does

Separate optimized S11 delta variant. It uses the same MAX/MIN definitions,
step-pair direction, independent frame envelopes, path logic, radius groups,
final tables, and editable charts as the original. It filters section points

data for a 16-angle/3-radius section from 48 to 12 section points per

7. TROUBLESHOOTING COMMAND-LINE PROBLEMS
========================================

Problem: Abaqus says -output-dir may not be used with Viewer.

Cause: The standalone -- separator was omitted from the U2 Viewer command.

Correct form:

    abaqus viewer noGUI="C:\python_aba\takeoutSFSM\extract_u2_local_selected_steps.py" -- --input-dir "C:\Data\ODBs" --output-dir "C:\Data\Results"


Problem: unrecognized arguments: --model.odb or --GdM_...odb

Cause: The ODB filename was written as if it were an option.

Correct form:

    --odb "model.odb"


Problem: ImportError for another extraction script.

Check the dependency summary in section 2. Put the required helper .py in the
same folder as the dependent script, and launch the dependent script by its
full path.


Problem: a numeric step input selects the wrong thing.

Step positions are 1-based. Frame indexes are zero-based. Use --list-steps to
confirm ODB order. For the delta scripts, use --step-pair; for the other
selected-step scripts, use --steps or --step-range.


Problem: an output workbook cannot be replaced.

Close that workbook in Excel and rerun. Excel can lock an open .xlsx file.


Problem: no progress appears during a long S11 delta run.

Add --verbose. A line is printed and flushed after each completed frame. One
large frame can still take time before its completion line appears.


Problem: COPEN is near 1E38.

Use the current CPRESS/COPEN script. It treats values at or above the default
absolute limit of 1.0E30 as undefined. Change the limit only if legitimate
model results could exceed it:

    --undefined-value-limit 1.0E35


Problem: the S11 run is too slow.

Use extract_pipe_s11_delta_step_pairs_four_angles.py and omit
--write-intermediate unless raw data are required. Limit the run to one ODB and
the necessary pipe elements when appropriate.
